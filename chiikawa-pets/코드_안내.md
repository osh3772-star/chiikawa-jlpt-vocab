# 치이카와 동작 베타 — 코드 안내

## 실행부터

`단어장.html`을 더블클릭해 열고 상단 **치이카와 동작 베타**를 켭니다.
전용 무대가 생기며, **걷기 보기**로 실제 좌우 원화 동작을 바로 확인합니다.
캐릭터 몸을 잡아 위로 들면 팔다리 포즈가 교대하고, 놓으면 낙하·착지합니다.
Escape는 잡기/낙하 상태를 안전하게 취소합니다. 베타를 끄면 기존 정적 대체로
돌아가며 학습 단어·알고 있음/모르겠음 기록은 바꾸지 않습니다.

이것은 기능적으로 연결한 **베타**이지 원작 외형 승인 또는 매끄러운 12프레임
완성본이 아닙니다. 현재 좌/우 **각 4키포즈**, 잡기 3+1키포즈, 착지 4키포즈입니다.
발 접지 해부학적 좌우가 확정되지 않았고 지지 발 고정 솔버는 아직 구현하지 않았습니다.
방향은 별개 원본 그림으로 표현하고 런타임 반전은 하지 않습니다.

## 이벤트 흐름

1. 학습 UI가 기존 `vocab:start/correct/wrong/complete/view` 이벤트를 보냅니다.
2. 엔진은 한 슬롯에 최근 반응만 보관하고, 1초가 지나면 폐기합니다.
3. 직접 잡기·낙하·착지를 끊지 않는 범위에서 대표 한 명에게 짧게 반응시킵니다.
4. 완료는 한 명이 먼저, 다른 한 명이 약 0.3초 뒤 반응하며 안전하게 정리합니다.
5. 캐릭터 코드는 학습 답안·단어 위치를 쓰지 않습니다. `correct/wrong`은
   채점 결과가 아니라 기존 버튼 이름(알고 있음/모르겠음)입니다.

베타 체크박스는 별도 `jlpt-pet-chiikawa-beta-v1` 설정만 저장합니다.
기존 `jlpt-local-vocabulary-v1`, `jlpt-pet-mobile-group-v1`은 유지됩니다.
초기에는 베타가 꺼져 있으며, 사용자가 켠 선택만 다음 방문에 기억합니다.

## 그림이나 속도를 바꾸려면

- **그림**: 새 PNG를 assets에 추가하고 config의 해당 `assetPath`를 바꿉니다.
- **한 프레임 영역**: `sourceRect:[x,y,width,height]`를 실제 PNG 픽셀 기준으로 지정합니다.
- **발바닥 정렬**: `pivot:[x,y]`는 셀 안 0~1 좌표이며 무대 바닥 기준점과 맞춥니다.
- **속도**: 프레임별 `durationMs`. 보행 거리 `rootDistancePx`는 실험실 240px
  기준 컨테이너에서의 한 주기 거리이며 실제 앱 크기에 맞춰 줄어듭니다.
- **방향**: `directionalWalks.left/right` 각각 별개 원본을 지정합니다. 반전 금지.
- **크기**: `uniformScale`은 시트 전체에 공통 적용합니다. 프레임마다 비율을
  달리하거나 가로·세로를 따로 늘리지 않습니다.
- **연속 원화 확장**: 8/12장이 실제로 다른 자세일 때만 배열을 늘립니다.
  정지 그림 복사본이나 이름만 다른 프레임으로 개수를 채우지 않습니다.

## 상태 전이

자율 대기 → 출발 자세 → 보행 순환 → 정지 자세 → 대기.
직접 잡기 → 잡힘 시작 → 들린 포즈 반복 → 놓기 → 낙하 → 착지 → 회복.
출발/정지 전환은 현재 짧은 끝점 자세이며, 별도 중간 원화 보강이 필요합니다.
포인터 취소·숨김·리사이즈·베타 해제는 캡처와 상대 예약을 정리하고 안전 복귀합니다.
등을 실제로 집는 뒷모습 원화가 아니라, 현재는 정면 잡힘 반응 포즈입니다.

## 검사 명령

```sh
python build_html.py
python build_preview.py
node --test tests/*.test.mjs
python -m unittest discover -s tests -p 'test_*.py' -v
```

패키지 설치나 CDN은 필요 없습니다. `docs/index.html`은 공개본이므로 별도
배포 요청 전에는 덮어쓰지 마세요. 다음 담당자가 변경할 때도 기존 사용자
작업을 reset/강제 덮어쓰기하지 말고 패치 적용 가능 여부부터 확인하세요.

## v3 작업본 추가: 근거 목록과 표시 관리

- `evidence_registry.py` / `sync_evidence_registry.py`: 영상 근거·설계·원화 승인
  대기를 분리하고, 원본 기록 해시와 동작/구간 참조를 검증합니다. 새 모션은
  활성화하지 않습니다. `chiikawa-pets/evidence/README.md`를 먼저 보세요.
- `evidence-registry.js`: 활성0/후보/별도 웹 배치안의 읽기 전용 상태 표시.
- `visibility-preferences.js`: 6캐릭터 표시와 일시정지를 별도 키로 저장/복원.
- `integration.js`: 개별/전체 꺼내기·넣기, 기존 창작 베타 표시, 모바일 dock UI.
- 엔진의 `setVisibleCharacters`, `getVisibleCharacters`, `focusCharacter`는
  표시 관리 API입니다. 모션 승인과 관계없으며 학습 데이터를 수정하지 않습니다.

현재 앱에서 이전 베타는 **기존 창작 동작 베타 (영상 재현 아님)**로 표시됩니다.
확인된 영상 조각과 혼동하지 않도록 이름을 분리했으며 기존 기능은 삭제하지
않았습니다. 실제 출처의 제한된 몸 자세와 웹 작성 경로를 결합하는 안도
별도의 검수 대상이지, 원작 비행 궤적을 복원한 것으로 세지 않습니다.

## v3 추가: 근거·표시·제한 미리보기

- `evidence_registry.py` / `sync_evidence_registry.py`: 설계·관찰 기록을 해시 스냅샷으로 묶고, ID/영상 구간/검토 범위를 교차 검증합니다. 영상 후보와 웹 배치안을 따로 세며 원작 동작 활성은 0으로 유지합니다. 영상의 재생 시각을 동작 길이로 변환하지 않습니다.
- `visibility-preferences.js`: `jlpt-pet-visibility-v1`에 6종의 표시 선호와 일시정지를 저장합니다. 학습 저장키와 무관합니다. 엔진 `setVisibleCharacters`는 캡처·공중·짝 예약을 즉시 해제합니다.
- `momonga-preview.js`: 검토된 정지 BODY의 안전한 웹 이동만 담당합니다. 전체 이동 영역 충돌검사 → 이미지 decode → 세대 토큰 검증 → 기본 actor 독점 숨김 → 1회 이동/정지 미리보기 → 현재 선호대로 복원합니다. 일반 영상 동작 재생기와 구분되어 있습니다.
- `limited_preview.py`: 검토 문서·원본 PNG 해시·한 자세·제한 승인 범위를 확인합니다. 빌더는 현재 registry의 동일 검토 ID와도 연결합니다. `prepare_momonga_preview.py`는 승인된 원본 바이트를 복사할 뿐 그림을 수정하지 않습니다.
- `art_quarantine.py`: 감사 M01–M03에 해당하는 모몽가 손상6포즈를 실행 결과에서 정상 idle 정지 그림으로 대체합니다. 원본은 삭제/수정하지 않고, 프로필 `quarantinedArt`에 사유를 남깁니다. idle을 원래 반응/매달림 동작처럼 소개하지 않습니다.

새 작업 사본 검수 순서: `python build_html.py` → `python build_preview.py` → `node --test tests/*.test.mjs` → `python -m unittest discover -s tests -p 'test_*.py'`. 테스트가 생성된 HTML도 검사하므로 처음에는 두 빌드를 먼저 실행합니다.
외형 원본 변경은 해당 hash 검토를 다시 수행해야 하며, 단순 `enabled=true`는 빌드 오류입니다. 기존 v2 배포 체크포인트는 별도 폴더에 그대로 보존합니다.
