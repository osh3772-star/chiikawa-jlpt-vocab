# 화면 밖 캐릭터의 자동 행동 기회 제외

이 후속 안전 수정은 개별 행동 확률을 높이지 않습니다. 캐릭터를 꺼내 둔 **선호**와 실제 화면에 보이는 **실행 자격**을 분리합니다.

## 이전 문제
모바일 가로 무대 밖 캐릭터는 CSS로 보이지 않거나 전부 잘렸지만 `hidden` 속성은 false였습니다. 자동 추첨과 공유 행동 슬롯은 이 속성만 검사해, 보이지 않는 친구가 행동을 시작하고 보이는 친구의 기회를 차지했습니다.

## 적용 범위
- 실제 캐릭터 사각형과 viewport, 모바일 dock의 교집합에 양의 면적이 있어야 화면 안으로 판정합니다. 완전히 가려진 배우는 제외하고 일부라도 노출되면 자격을 유지합니다.
- 자동 추첨, 공유 슬롯 경쟁, 학습 반응의 대표 선택에 같은 판정을 씁니다.
- 화면 밖 비물리 행동은 idle로 정리합니다. 진행 중 직접 잡기/낙하 같은 물리 상태는 안전 정리와 우선권을 보존합니다.
- 모두 화면 밖이면 유휴 RAF가 멈추고 스크롤/레이아웃 변화로 다시 계산합니다.
- 특정 학습 반응 대상이 스크롤 밖으로 사라지면 대기 반응을 버려 유효기간 동안 슬롯을 막지 않습니다.
- 6종 선택 체크, 저장 선호, 행동 가중치, 기존 대기시간 값, 학습 데이터는 바꾸지 않습니다. 20초 쿨다운이나 새로운 반복 방지 정책은 이 수정에 포함하지 않습니다.

## 검증 범위
실제 engine + 테스트용 DOM/20ms RAF, 같은 seed437·500px viewport·120초 조건에서 완전히 가려진 시사/모몽가/랏코의 비-idle 시작이 11/8/14회에서 0/0/0회로 바뀌었습니다. 보이는 캐릭터의 기회가 늘어나는 이유는 숨은 캐릭터가 슬롯을 차지하지 않기 때문이며 확률표 상향이 아닙니다. 전원이 보이는 desktop 단독 6×1시간·그룹 3×1시간·pause/reduced/hidden lifecycle 결과와 추첨표는 이전과 동일했습니다.

이는 실제 모바일 사용 시간·배터리·RAM 측정이 아닙니다. 최종 source와 내장 HTML engine 일치는 확인했으며 실제 좁은 브라우저 검수는 별도 기록합니다. `tests/viewport-eligibility.test.mjs`는 clip 경계, 선택 유지, 스크롤 자격 교대, RAF 멈춤/재개, 보이는 대표 선택, 대기 대상 이탈을 검증합니다.

## 실제 좁은 브라우저 검수
약 485 CSS px에서 6종 선택 선호와 캐릭터당 한 actor를 유지하면서, dock 첫 구간의 앞 3명/스크롤 뒤 구간의 뒤 3명이 정확히 visibility를 교대했습니다. 일시정지 중 스크롤 재계산, 문서 아래로 내려가 전원이 화면 밖일 때 숨김, 다시 선택해 화면 안으로 복귀, 좁은 창 드래그/Escape의 비정상 고착 없음도 확인했습니다. 원래 창 크기로 복원했습니다. 이 실제 UI 검수에서는 추첨 빈도나 RAF 횟수를 측정하지 않았습니다.
