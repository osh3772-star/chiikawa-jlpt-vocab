# EP2 상체 4키포즈 제한 미리보기 — v4 작업본

이것은 자연스러운 최종 애니메이션의 완료본이 아닙니다. 실제 관찰한 네 자세를 참고한 파생 그림을 한 번씩 교체하여, 외형·기준점·취소 구조를 검수하는 중간 단계입니다.

## 관찰 범위와 구현
- 확인된 순서: A 정면 말린 앞팔 → A1 오른3/4 앞팔 내림 → B 오른옆 앞팔 내림 → C 정면 복귀/앞팔 내림.
- 실제 출처: https://www.tiktok.com/@chiikawa.anime/video/7678574490330107152
- 원자료는 상체만 보입니다. 아래 몸/발을 재구성하지 않고, 명시적인 상체 창틀 아래를 잘라 표시합니다.
- 파생 PNG 원본 바이트를 보존합니다. 포즈별 초기 등비 축척과 CSS sourceRect clip만 사용하며 그림 변형/좌우미러/회전/크로스페이드/보간을 하지 않습니다.
- 표시 폭은 A/C120px, A1/B114px, 공통 창140×124px입니다. 작은 측면폭 차이를 보존하면서 원본 생성 크기의 약16–17% 차이를 정규화한 수치이며 원작 신체치수라고 주장하지 않습니다.
- 하단 clip은 A1014, A1958, B968, C1022 원본 y입니다. 알파 먼지 아래를 새로 그리는 대신 창틀 뒤에 가립니다. 네 포즈의 하단을 같은 창 바닥에 맞춥니다.
- 420/320/450/600ms는 제작한 웹 UX 리듬입니다. 영상 캡처 직전 재생 시각의 차이를 정확한 프레임 시간으로 변환하지 않았습니다.
- A→A1→B→C 한 번 후 C 정지 유지. 실행 중 반복 클릭은 대기열을 만들지 않습니다. 종료 후 명시적 재호출은 숨김 상태에서 A로 초기화할 뿐 C→A 동작/역재생을 만들지 않습니다.
- 동작 줄이기/일시정지 상태의 명시 호출은 A 정지 자세만 표시합니다.
- 숨김/Escape/창변경/포커스이탈/학습입력/일시정지 변경/엔진 재마운트는 대기 중 decode까지 취소합니다. 원래 actor는 현재 표시 선호에 맞춰 복원합니다.
- 모몽가 미리보기와 서로 독점합니다. 시작/종료로 학습 데이터 저장키를 변경하지 않습니다.
- 자동 취소/종료 때 빈 무대 공간을 유지하며 명시적인 무대 닫기만 접습니다.

## 아직 미완료
- A1→B 및 B→C 사이 연속 영상 관찰/세부 연결 자료가 부족합니다. 확인되지 않은 중간 각도·발동작을 합성하지 않습니다.
- 자연스러운 최종 애니메이션에는 충분한 원작 동작 구간 관찰, 방향별 일관된 추가 연속 프레임, 연결 속도/외형 떨림 검수가 필요합니다. 현재 네 그림을 복제하여 12프레임이라고 부르지 않습니다.
- 네 포즈의 얼굴·귀 높이/실루엣 변화와 희소한 교체 리듬은 실제 전환 QA 대상입니다. 원작 전체 동작 활성 registry는 여전히0입니다.
- 다른 다섯 캐릭터의 개별 동작/짝 행동/배경 선택 완료를 뜻하지 않습니다. 배경·다크모드 기능은 이 작업에 추가하지 않았습니다.

## 파일
`static_cameo.py`는 정확한 이미지 SHA/포즈 순서/허용 등비 crop/UX시간을 검증합니다. `chiikawa-pets/static-cameo.js`는 공통 독점 취소와 상체 포즈 표시를 담당합니다. `chiikawa-pets/limited-previews/chiikawa-ep2-a.json`은 초기 A 단독 작업에서 확장된 네 자세 메타데이터입니다.

## 별도 성능 후속 검토
현재 paused/reduced 상태에서도 기본 엔진 RAF가 유지됩니다. 누수가 확인된 것은 아니지만, 향후 입력/레이아웃 변경시에만 정적 actor를 갱신하는 구조를 검토할 수 있습니다. 먼저 현재 포인터 캡처·스크롤 dock·직접 조작·표시 복원 테스트를 보존한 상태에서 별도 작은 변경으로 측정해야 합니다. 이번 키포즈 작업에서 엔진 루프 구조를 동시에 바꾸지 않았습니다.

## 실제 캐릭터 행동으로 연결하는 후속 게이트
미리보기 버튼은 임시 검수 통로이며 최종 목적은 여섯 캐릭터의 고유한 상호작용입니다. 다음 조건을 각각 통과하면 관찰된 조각을 실제 actor 상태기계의 제한 action으로 연결할 수 있습니다.
1. 독립 아트 검수: 해당 방향/접점/포즈 범위와 다른 캐릭터와의 일관성 확인.
2. 시간·앵커 검수: 실제 표시 크기에서 전환 튐과 제작 리듬을 검수하며 정확한 원작 타이밍과 구분.
3. 학습방해 검수: 안전영역, 빈도/중복 제한, 입력우선, 모바일/동작줄이기, 취소/복원 확인.
4. 개별 캐릭터 상태기계: 기존 동작의 선점·종료·중단·resume 정책을 명시하고 관찰조각 action과 작성한 웹 event mapping을 별도로 등록.
현재 공통 preview coordinator와 engine의 begin/endExternalPresentation은 독점·정리 경계만 제공하며, 이를 원작 전체동작 승인으로 간주하지 않습니다. 이후 연결에서도 없는 하체/발/연속 구간을 재생했다고 표시하지 않습니다.
