# v5 제한 관찰 조각 통합

이 버전은 6종의 자연스러운 최종 애니메이션 완성본이 아닙니다. 원작 완전 동작 registry 활성화는 여전히 0입니다. 검수된 정지 포즈의 명시적 제한 확인과 안전한 웹 배치만 제공합니다.

## 사용과 학습 우선
- 캐릭터별 꺼내기/넣기와 일시정지는 항상 접근할 수 있습니다.
- 실험 도구는 기본 접힌 **동작 미리보기 · 검토용** 영역에 모았습니다. 펼치기만으로 재생하지 않습니다.
- 실제 학습 입력, Escape, 숨김, 다른 미리보기, 창/페이지 변경은 준비 중인 이미지도 취소합니다.
- 자동 종료는 예약한 무대 높이를 유지합니다. 사용자가 무대나 전체 검토영역을 명시적으로 닫을 때만 접습니다.
- 기본 캐릭터와 별도 미리보기의 독점 소유권을 공유하여 같은 캐릭터가 중복 표시되지 않게 합니다.

## 표현 범위
- 치이카와 EP2: A→A1→B→C 상체 4포즈, 제작 UI 리듬. 중간 각도·하체·발·보간·역재생 없음.
- 하치와레 EP5: 같은 봉지를 두 앞발로 지지한 A→B 상체 2포즈. 개봉·먹기·내리기 없음.
- 우사기 EP6: A→B 관찰 조각 뒤 숨김. C는 별도 버튼의 나중 정지 컷이며 착지로 연결하지 않음. 추가 관찰/후보 아트는 이 구성의 자동 승인으로 취급하지 않음.
- 모몽가: 영상 자세 참고 파생 정지 몸체 + 별도 제작 웹 경로. 날갯짓·이륙·착지·원작 이동 속도 재현 아님.
- 시사: 파생 정적 몸체·병·줄기 1장 + 별도 제작 고정 UI 컵. 원작에서는 쿠리만쥬가 잔을 든다는 설명을 유지합니다. 몸·줄기·액면 움직임이나 관계 장면 재현은 없습니다.
- 기존 창작 치이카와 걷기/들기 베타는 별도 표기를 유지합니다. 영상 근거 애니메이션으로 재분류하지 않습니다.

## 구현 위치
`integration.js`는 UI·학습 이벤트·독점 조정을 담당합니다. 각 `*-preview.js`, `static-cameo.js`, `*-pose.mjs`, `*-fragment.mjs`는 제한 표현의 취소 가능한 상태기계입니다. `fragment_assets.py`와 JSON은 검수된 PNG 바이트/크기/순서를 고정합니다. 원화를 늘리거나 픽셀을 변형하는 대신 실제 source crop과 등비 크기·앵커를 사용합니다.

`pet-engine.js`의 최소 RAF 개선은 일시정지/동작줄이기의 안정된 상태에서만 유휴 반복을 멈춥니다. 드래그·물리·대기 반응은 유지하고 레이아웃/입력 변경으로 다시 계산합니다. 모의 스케줄러의 감소 결과는 실제 배터리 절감 또는 메모리 누수 해결 수치가 아닙니다.

## 이미 확인된 범위와 다음 게이트
v4 실제 브라우저에서 4포즈(A1 포함) 제한 전환, pending Escape/단어 탐색 취소, 약 485px 좁은 창의 정적 치이카와/모몽가 표시를 확인했습니다. OS 동작 줄이기 및 320px 실기 검증은 이 결과에 포함되지 않습니다. v5 새 통합/RAF의 실제 브라우저 검수 결과는 별도 기록해야 합니다.

다음 실제 pet 행동 연결은 독립 아트 검수, 시각·앵커·전환 품질, 학습 비방해, 캐릭터 상태기계 검수를 통과해야 합니다. 부족한 연속 프레임과 관찰되지 않은 동작은 추가 자료 없이 만들어 완료 처리하지 않습니다.

## 정적 소품 보수와 전환 품질의 구분
치이카와 분홍 사스마타와 우사기 노랑 직선봉은 검수된 정적 소품 보수입니다. 자율 `sasumata` 확률은 두 종 모두 0으로 유지합니다. 실제 126px 엔진 표시에서 귀·봉끝·발 clip은 없었지만, 치이카와의 기존 무기 구도는 idle보다 몸이 약 25% 작고 발이 약 20px 위로 보였습니다. 따라서 정체성 보수 합격을 자연스러운 idle→무기 전환 합격으로 부르지 않습니다. 임의 몸 변형이나 미검수 앵커 이동 없이 다음 원화/등록 검토에 남깁니다.

초기 접힌 Momonga/EP2 이미지에는 src를 지정하지 않고 명시적 시작 때만 지정합니다. 실제 브라우저에서 초기 src 없음, 명시 시작·취소·재시작을 확인했습니다. dataURI 문자열은 여전히 HTML에 포함되므로 이것을 파일 크기나 RAM 절감량으로 표현하지 않습니다.

## 재현 명령
저장소 루트에서 아래 순서로 실행합니다. 두 생성 파일은 배포 소스가 아니라 로컬 산출물이며 일부 기존 Python 검사가 두 파일을 읽습니다.

```sh
python build_html.py
python build_preview.py
node --test tests/*.test.mjs
python -m unittest discover -s tests -p 'test_*.py'
```

`build_preview.py`를 생략하면 초안 미리보기 파일을 읽는 검사가 실패합니다. 최종 검증은 두 builder 실행 후 Node 190개 + Python 45개, 총 235개 PASS였습니다.

캐릭터 관리(일시정지 버튼·꺼내기 설정·가로 무대·근거·검토 영역)에 초점이 있으면 네 방향키는 단어 이동/채점을 실행하지 않습니다. 일반 학습 영역의 방향키와 설정의 기본 Space/Enter/Escape 동작은 유지합니다.
